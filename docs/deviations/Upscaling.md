# Upscaling

Rules, Kind legend and cross-cutting records: [README](README.md).

Consumer: `package\Shaders\ISSSLRRaytracing.hlsl`.
Feature classification: **core (doodlum FO4 release lineage)** (rule 4).

Upscaling, FrameGeneration and MotionVectorFixes are maintained in-house. These comparisons
describe main's existing implementation, not an upstream-conversion plan or parity claim.
The FO4 shader copies, settings keys, SDK inputs, render scheduling and presentation are retained.

| Forced | Shaders add `SharedData::MipBias`; engine samplers are never biased (upstream `CreateSamplerState` only caps anisotropy) | `SamplerBias` swaps the anisotropic engine samplers for `MipLODBias = MipBias` copies around `DrawWorld::DeferredPrePass` and `Forward`, and stays. The shader-visible `SharedData::MipBias` therefore means the bias a shader must still add: `SAMPLER_MIP_BIAS` (`FO4ShaderData.hlsli`; cbuffer offset 588 unchanged, the member is renamed under the define) resolves it to 0, so upstream's `SampleBias(..., MipBias)` and the staged `TerrainVariation.hlsli` `SampleLevel` land on the biased sampler at upstream's lod + MipBias instead of twice that. The Upscaling feature injects it (contributor `UpscalingSamplerBias`, only while Upscaling is loaded) on every target with a reconstructed shader that is drawn inside either window, so future ports of shaders that read `MipBias` upstream (Utility, DistantTree, Water, RunGrass) are correct without edits; a target with no reader compiles to unchanged bytecode. Targets and evidence: `kDeferredPrepass` (BSDFPrePass passes); `kDistantTree` (group 1 is drawn by DeferredPrePass, engine-facts Distant-tree pass placement); `kEffect` (deferred BSLighting properties build BSEffect passes in modes 18/24, engine-facts Deferred-mode BSLighting passes; Forward also draws Effect batch 0). Drawn in a window but never injected, because FO4 owns no reconstructed shader for them and stock bytecode reads no `MipBias`: `kUtility` (BSUtility passes in the same modes), `kBsSky` and `kBsLighting` (Forward draws Sky batch 7, cloud group 14 and Lighting batch 8, engine-facts Post-composite world order); add them to the define when a reconstruction exists. Not in either window: Particle, BloodSplatter, Water (PostResolveDepth batch 10), and the compute and image-space targets. Window contents also explain why the swap stays: it cannot be dropped per window, and a prepass variant that has not compiled or failed to compile draws stock bytecode through `AcquireNativeReplacementWrapper`, which has no shader-side bias; per-draw sampler switching would need the lazy sampler-bind and dirty-mask path (engine-facts PS sampler shadow inputs) reverse engineered. Gap: the override biases only `D3D11_FILTER_ANISOTROPIC` samplers, while shader-side `SampleBias` biases any sampler, so under `SAMPLER_MIP_BIAS` a non-anisotropic sampler loses the bias it would get upstream. The Terrain Variation slots are anisotropic: `BSDFPrePassShader` SetupTechnique (OG 0x2862000 / NG 0x20A63C0 / AE 0x2203560) binds all 16 landscape slots wrap with filter 3; SetupMaterial (OG 0x2862870 / NG 0x20A6FA0 / AE 0x2204140) writes layers 1-3 and t13/t15 wrap and anisotropic; SetupGeometry (OG 0x2863C20 / NG 0x20A83A0 / AE 0x2205540) binds t14 clamp and anisotropic; mesh t0 follows the material clamp mode with an anisotropic filter. A RenderDoc capture (Vault 111) confirmed it: landscape s0-s11, s13 and s15 Wrap + Anisotropic16, s14 ClampEdge + Anisotropic, mesh s0-s2 Wrap + Anisotropic on all 44 flagged draws, and the LOD variant s0-s2 ClampEdge + Anisotropic with s13/s15 Wrap | `FO4ShaderData.hlsli`, `features/Upscaling/src/{ShaderDefines.h,Upscaling.cpp}`, `SamplerBias.cpp`, `TemporalRenderHooks.cpp` |
| Forced | Jitter and dynamic-resolution publication into Skyrim viewport | Publish equivalent offsets and RenderTargetManager ratios after FO4's native UpdateTemporalData; preserve top-left active-region proxies and engine-image-space family routing | engine-facts Dynamic-resolution history / Main camera preparation; FO4's state/target-manager layout and native updater are different | `TemporalRenderer.cpp`, `TemporalRenderHooks.cpp`, `DynamicResolution.cpp` |
| Divergence | Pre-tonemap SR with upstream exposure/HDR policy | Post-tonemap/LUT gamma-2.2 R8G8B8A8_UNORM SR and automatic exposure | Main's explicit color contract; no engine evidence proves pre-tonemap integration impossible | `TemporalResolve.cpp` `SuperResolutionRequest::color`, `TemporalFrameGenerationInputs.cpp` frozen color |
| Divergence | Direct upstream FidelityFX FSR3 dispatch | Streamline FSR3/FSR4 D3D12 providers and typed shared input transport; FO4 encoder's FSR branch writes undilated motion to u2 | In-house SDK/backend architecture; upstream instead passes native motion directly and binds u2 only for DLSS | `Streamline.{h,cpp}`, `SuperResolutionProviders.cpp`, `DX12SwapChain.cpp`, `FO4/Upscaling/EncodeTexturesCS.hlsl` |
